# Import process

<!-- Explains the implemented import lifecycle, API and provider boundaries, progress, persistence and retry. -->

Imports turn a photo, PDF or text source into Thing fields, then research supporting documents and suggestions. Fastify controls the workflow and persistence. OpenAI extracts facts, proposes field mappings and researches non-instance-specific field context. All application API calls below are authenticated and owner-scoped. The adapters use the [official OpenAI TypeScript SDK](https://developers.openai.com/api/docs/libraries). [Prompts](../../server/src/providers/ai/prompts.ts) and [response/tool schemas](../../server/src/providers/ai/schemas.json) are authored separately from transport. `pnpm ai:generate` generates their TypeScript types; `pnpm ai:check` checks drift.

## Sequence

1. **Client uploads the source.** [AddThing](../../src/app/features/add-thing/add-thing.ts), [PasteText](../../src/app/features/add-thing/paste-text.ts) or [ImportSources](../../src/app/features/things/import-sources.ts) calls `ThingsStore.startImport(file, thingId?)`. Pasted text becomes a `text/plain` file. [AttachmentsService](../../src/app/core/data/attachments.service.ts) sends multipart `POST /api/attachments`; the [attachment route](../../server/src/routes/attachments.ts) validates the file, stores it privately and returns its attachment ID. Extracting an existing attachment starts at step 2.

2. **Client queues the import.** [ThingsStore](../../src/app/core/state/things.store.ts) calls [ImportsService.start](../../src/app/core/data/imports.service.ts): `POST /api/things:import` with `{ attachmentId, thingId? }`. The [route](../../server/src/routes/imports.ts) calls [startImport](../../server/src/db/entities/imports.ts), which creates an `Importing…` skeleton when no Thing ID was supplied, links the source and persists a `QUEUED` job. The response is `202 { importId, thingId, status }`; the route wakes the runner.

3. **Client displays persisted progress.** The store loads `GET /api/things/{id}` and the UI opens the returned Thing. [ThingLoader](../../src/app/features/things/thing-loader.ts) starts an authenticated `GET /api/things/{thingId}/stream` through [watchThing](../../src/app/core/api/thing-stream.ts). Throughout the remaining steps, server commits trigger `data.changed` notifications; the [SSE handler](../../server/src/routes/imports.ts) reads current state and sends revisioned `thing.snapshot` events. The store updates fields and import status, and reloads related collections when revisions change. Reconnecting reads persisted state again.

4. **Server picks up the job.** [JobRunner](../../server/src/application/jobs/runner.ts), wired in [app.ts](../../server/src/app.ts), processes persisted imports and assistant work serially. A [database session lock](../../server/src/db/job-lease.ts) permits one active runner per database. [ImportProcessor.next/run](../../server/src/application/import/processor.ts) selects the oldest queued import and drives the stages below, recording token usage, tool calls and elapsed time.

5. **AI extracts source facts — `EXTRACTING`.** The processor reads the private blob and calls [OpenAiImports.extract](../../server/src/providers/ai/openai-imports.ts). This sends `POST https://api.openai.com/v1/responses` with text, an image or a base64 file, allowed categories and a JSON output schema. The model returns document metadata, transcription and candidate Things with quoted facts, page references and sensitivity flags. This call has no tools. The server [validates extraction](../../server/src/application/import/mapping.ts), saves it in `bt.imports.extraction` and updates attachment metadata. Ordinary API/SSE responses omit the full extraction.

6. **Server resolves the destination Things.** One candidate is selected automatically. Multiple candidates change the job to `AWAITING_SELECTION` and release the runner. API clients can send `POST /api/imports/{id}:confirm` with candidate IDs and destination Thing IDs (`null` creates a Thing; skipped candidates are omitted). [confirmImport](../../server/src/application/import/commands.ts) allocates targets transactionally, reuses the skeleton for the first new Thing, links the source to each target and requeues the job. Processing resumes using the saved extraction. The current UI displays progress and retry but has no candidate-selection action.

7. **AI maps each candidate — `MAPPING`.** The processor awaits [OpenAiImports.selectFieldSets](../../server/src/providers/ai/openai-imports.ts) and separate `OpenAiImports.mapFacts` calls:
   - **Choose field sets:** a Responses request asks the model to call `search_field_sets(categoryId, terms)`. When a response contains a `function_call`, `runRegistryConversation()` validates its arguments and invokes the processor's tool callback. The callback runs [registry search](../../server/src/application/registry/search.ts). The adapter adds the result as `function_call_output` and calls Responses again. This loop ends when the model returns schema-valid set IDs.
   - **Fill fields:** the processor expands the selected sets' mandatory dependencies and calls `mapFacts` with the extracted Thing, selected sets and up to 20 facts per awaited request. Each batch starts a fresh conversation with a Thing definition and mapping rules. The prompt selects the Thing's name, category and terms and contains set IDs/names, field IDs/names/descriptions/schemas/sensitivity, and the batch's fact IDs/labels/values/quotes/sensitivity. The model matches selected-set fields first, then searches standalone definitions. Every fact is accounted for in registry `values`, `customFactIds` or `discardedFactIds`. Custom fields require identifiable value in operating, maintaining, identifying or administering the Thing; unexplained markings and irrelevant information are discarded. Its tool loop exposes `search_fields(labels)` and retains outputs, encrypted reasoning and tool results within that batch; calls use `store: false`. The processor rejects omissions, conflicting dispositions, duplicate addresses and facts outside the batch.
   - **Commit each stage:** the processor validates retrieved IDs, category eligibility, field membership and value types through [applySelectedSets/applyFactMapping](../../server/src/application/import/mapping.ts). It saves selected sets first, then each completed decision batch, publishing progress after each commit. Selection and decisions are stored in the private extraction JSON in the same transaction as Thing fields. Useful custom fields and conflicting evidence retain source references and sensitivity; owner edits and clears are preserved. Unedited custom fields retained by older interrupted imports are reconciled as their facts are processed. All targets finish mapping before discovery starts.

8. **AI researches each Thing — `DISCOVERING`.** [buildResearchThing](../../server/src/application/import/mapping.ts) collects populated fields classified as `instanceSpecific: false` across selected sets, standalone definitions and explicitly classified custom fields. Labels, descriptions, addresses and typed values accompany the context; zero, false and empty strings remain populated. Unclassified fields default to instance-specific. Sensitivity independently controls application masking. Missing eligible fields become `emptyFields`; populated public context becomes `knownFields`; owner-cleared destinations are excluded. Raw uploaded text and other instance-specific values stay outside public-search input. [Category instructions](../../server/src/providers/ai/prompts.ts) define the documents to find, with a fallback for new categories. [OpenAiImports.findResources](../../server/src/providers/ai/openai-imports.ts) uses hosted `web_search`, then a tool-free request structures the report against retrieved URLs. The persisted `ImportDestination` links an extracted subject to the Thing receiving its results. The [research workflow](../../server/src/application/import/research.ts) uses one search with the full configured web-call budget and considers at most three documents. Up to three retrieved pages are fetched through the protected download provider; their document and image links, including embedded JSON download metadata, become observed resource URLs. Category documents take priority over supplementary specifications. Physical objects also receive an official product-photo search.

9. **AI extracts reference fields; server commits results.** The server downloads cited PDFs through the [PDF provider](../../server/src/providers/web/pdf.ts), preserving its HTTPS, DNS, redirect, size and content checks. The contained `extractDocument` task receives one document, public subject context and up to 20 requested field definitions. It has no search or write tools. It must establish applicability with page/quote evidence, including variant, region and version when relevant, before proposing supported fields. The matching official download-page context can establish applicability for a family manual; conflicting variants remain rejected. The server validates requested addresses, schema types and evidence bounds. Applicable documents become private attachments; each value batch fills still-empty eligible fields with `DISCOVERY` provenance and attachment/URL/page/quote references under a Thing row lock. Owner edits, clears and removed sets are rechecked at each commit. Progress is published after each document and value batch. Documents are accepted up to 100 MB (100,000,000 bytes). PDF.js reads embedded text locally from every page, retaining original page labels and line breaks, with a 1,000,000-character limit. The model receives extracted text and prefers English sections while deduplicating translated repetitions. Source extraction saves the local text without asking the model to transcribe it again. PDFs without embedded text use vision within 25-page and 40 MB limits. Text extraction does not read images or guarantee table reading order. Research allows five field batches per document. Unsupported values remain absent.

10. **Server attaches a product photo.** A retrieved official model page supplies the image URL and evidence for its model and variant. Images use the same HTTPS, DNS, redirect and streamed-size protections as documents. JPEG, PNG and WebP headers must identify dimensions of at least 200 × 200 pixels and at most 16 million pixels before decoding; bytes must decode successfully. Image downloads are limited to 5 MB and the configured upload limit. The private attachment retains its source URL and `DISCOVERY` title provenance. The server selects it as the main image only while the image remains unset and has no owner edit marker. Explicit image choices, clears and unlinking the main image set that marker. Image failures preserve documents and fields.

11. **Server records outcomes and finishes.** Applicable attachments and completed field batches are persisted for retries. Saved bytes and completed batches are reused. A research retry searches once for alternatives when the preceding attempt recorded warnings. Rejected document URLs, reasons and limits are persisted; unchanged deterministic size and model-input rejections skip downloading on retry. Research receives document limits and rejected URLs to find alternatives within the search budget. Cited names retain their persistence and deduplication behaviour. Import research saves category documents and a product photo. Assistant chat uses a separate question-based research method that returns cited findings to the conversation. `researchOutcomes` reports `FOUND`, `UNAVAILABLE`, `RETRIEVAL_FAILED` or `BUDGET_EXHAUSTED` for resources and missing field addresses. After source extraction and mapping, the job becomes `COMPLETE`. Optional research failures add owner-scoped `warnings` with the reason, source URL, retry eligibility and relevant limits; committed results remain available. The Thing shows “Imported; some research could not complete.” Transient warnings expose “Retry research”; changed upload limits also permit reconsidering size rejections.

## Failure and retry

[ImportProcessor](../../server/src/application/import/processor.ts) enforces timeouts and tool budgets. Field-set selection and each fact-mapping batch have separate registry tool-call budgets, controlled by `IMPORT_TOOL_ROUNDS`; the extraction/mapping attempt shares one timeout. An extraction/mapping failure becomes `FAILED` before targets are allocated, or `INCOMPLETE` afterwards; committed results remain available. [ImportProgress.retry](../../src/app/features/things/import-progress.ts) calls `POST /api/imports/{id}:retry`, which requeues failed/incomplete jobs and completed jobs with warnings. Research retries preserve extraction, mappings and saved attachments. Core extraction, mapping and persistence failures retain failure statuses. Uploads exceeding the configured size limit return HTTP 413. The application uses `ExtractedThing` and `extractedThings`, while persistence and provider wire data retain `candidates`. Public research receives a separate `ResearchThing`. Saved extraction, targets and discovery responses are reused; completed targets and committed fact batches are skipped; unfinished facts are retried while preserving earlier values and user edits. Source facts remain in private processing input, including discarded facts.

SDK transport retries are disabled; document validation retries and persisted application retries have separate bounds. On restart, queued jobs resume; interrupted extraction, mapping or discovery is marked `FAILED` with `interrupted` for explicit retry. `GET /api/imports/{id}` exposes status, candidate summaries while awaiting selection, result IDs, error codes, research outcomes, optional research warnings and usage metrics. Usage entries identify the task, model, tokens and request latency; aggregate token counts remain available. See [README configuration and limits](../../README.md#ai-imports).

## PDF text validation

On 5 October 2026, the [Samsung RF65A967FS9 multilingual manual](https://org.downloadcenter.samsung.com/downloadfile/ContentsFile.aspx?CDSite=UNI_UK&OriginYN=N&ModelType=N&ModelName=RF65A967FS9&CttFileID=8203148&CDCttType=UM&VPath=UM%2F202106%2F20210629104532259%2FT-TYPE_RF9000A_DA68-04023P-01_EN_IT_ES_PT_EL.pdf) (45,792,215 bytes, 428 pages) produced 533,312 characters of page-labelled text in about 1.9 seconds. A mocked provider check confirmed one text request and preservation of the full extraction through application validation. No live model request was made; fact recall, multilingual deduplication and table interpretation remain unmeasured.

## Fact selection evaluation

On 4 October 2026, one live `gpt-5.6-sol` run over a labelled synthetic Neff hob fixture passed all three expected decisions: Z-number `0015` mapped to `appliances.neff` / `appliances.zNumber`, installer reference `ABC-12` retained as a custom field, and unexplained marking `V/C` discarded. Application validation accepted the complete response and preserved the identifier's leading zeroes.

The run used one read-only registry search and two model requests, totalling 4,847 input tokens (2,094 cached), 199 output tokens and 6.2 seconds of provider request time. Results and usage are saved locally in ignored `test-results/fact-selection-evaluation.json`. This checks one fact-mapping batch; broader usefulness, extraction and full-import quality remain unmeasured.

## Reference extraction model evaluation

`DOCUMENT_EXTRACTION_MODEL` independently selects the contained task's model and defaults to `OPENAI_MODEL`. Model defaults remain unchanged. Text and image inputs and Responses structured outputs are supported by the compared models; [OpenAI file-input guidance](https://developers.openai.com/api/docs/guides/file-inputs) describes PDF text and page-image processing.

Run `node --import tsx --env-file=.env scripts/evaluate-document-extraction.ts` for a **paid** comparison on [labelled synthetic fixtures](../../server/test/fixtures/reference-documents.ts). `--models=model-a,model-b` selects models; `DOCUMENT_EVAL_RATES` supplies USD-per-million input, cached and output rates for additional models. Results, per-task usage, latency and cost including retries are saved in ignored `test-results/document-extraction-evaluation.json`.

The baseline requires all six supported values, correct applicability for all four documents, no incorrect values and verbatim quotes on the labelled pages. It covers a family manual, a typed specification (zero, false, empty text and money), a policy version and an incompatible variant. Two fixtures are PDFs and two are text. Image extraction capability is documented; image quality is unmeasured.

Measured on 4 October 2026, one run per model over the same four documents:

| Model          | Fixtures passed | Supported-field recall | Incorrect values | Citation errors | Total latency | Estimated task cost (USD) |
| -------------- | --------------- | ---------------------- | ---------------- | --------------- | ------------- | ------------------------- |
| `gpt-5.6-sol`  | 4/4             | 100%                   | 0                | 0               | 10.8 s        | $0.022344                 |
| `gpt-5.4-mini` | 3/4             | 33%                    | 0                | 0               | 4.8 s         | $0.003093                 |

This baseline measures contained extraction; retrieval success, full-import cost, image quality and broader document coverage remain unmeasured. Defaults require broader evaluation before changing. Costs use the standard rates on the official [Sol](https://developers.openai.com/api/docs/models/gpt-5.6-sol), [5.4 Mini](https://developers.openai.com/api/docs/models/gpt-5.4-mini) and [4.1 Mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini) pages, with input images included in provider token usage. All 12 requests completed without retries.
