# Import process

<!-- Explains the implemented import lifecycle, API and provider boundaries, progress, persistence and retry. -->

Imports turn a photo, PDF or text source into Thing fields, then research supporting documents and suggestions. Fastify controls the workflow and persistence. OpenAI extracts facts, proposes field mappings and researches non-instance-specific field context. All application API calls below are authenticated and owner-scoped. The adapters use the [official OpenAI TypeScript SDK](https://developers.openai.com/api/docs/libraries). [Prompts](../../server/src/providers/ai/prompts.ts) and [response/tool schemas](../../server/src/providers/ai/schemas.json) are authored separately from transport. `pnpm ai:generate` generates their TypeScript types; `pnpm ai:check` checks drift.

## Sequence

1. **Client uploads the source.** [AddThing](../../src/app/features/add-thing/add-thing.ts), [PasteText](../../src/app/features/add-thing/paste-text.ts) or [ImportSources](../../src/app/features/things/import-sources.ts) calls `ThingsStore.startImport(file, thingId?)`. Pasted text becomes a `text/plain` file. [AttachmentsService](../../src/app/core/data/attachments.service.ts) sends multipart `POST /api/attachments`; the [attachment route](../../server/src/routes/attachments.ts) validates the file, stores it privately and returns its attachment ID. Extracting an existing attachment starts at step 2.

2. **Client queues the import.** [ThingsStore](../../src/app/core/state/things.store.ts) calls [ImportsService.start](../../src/app/core/data/imports.service.ts): `POST /api/things:import` with `{ attachmentId, thingId? }`. The [route](../../server/src/routes/imports.ts) calls [startImport](../../server/src/db/entities/imports.ts), which creates an `Importing…` skeleton when no Thing ID was supplied, links the source and persists a `QUEUED` job. The response is `202 { importId, thingId, status }`; the route wakes the runner.

3. **Client displays persisted progress.** The store loads `GET /api/things/{id}` and the UI opens the returned Thing. [ThingLoader](../../src/app/features/things/thing-loader.ts) starts an authenticated `GET /api/things/{thingId}/stream` through [watchThing](../../src/app/core/api/thing-stream.ts). Throughout the remaining steps, server commits trigger `data.changed` notifications; the [SSE handler](../../server/src/routes/imports.ts) reads current state and sends revisioned `thing.snapshot` events. The store updates fields and import status, and reloads related collections when revisions change. Reconnecting reads persisted state again.

4. **Server picks up the job.** [JobRunner](../../server/src/application/jobs/runner.ts), wired in [app.ts](../../server/src/app.ts), processes persisted imports and assistant work serially. A [database session lock](../../server/src/db/job-lease.ts) permits one active runner per database. [ImportProcessor.next/run](../../server/src/application/import/processor.ts) selects the oldest queued import and drives the stages below, recording token usage, tool calls and elapsed time.

5. **AI extracts source facts — `EXTRACTING`.** The processor reads the private blob and calls [OpenAiImports.extract](../../server/src/providers/ai/openai-imports.ts). This sends `POST https://api.openai.com/v1/responses` with text, an image or a base64 file, allowed categories and a JSON output schema. The model returns document metadata, transcription and candidate Things with quoted facts, page references and sensitivity flags. This call has no tools. The server [validates extraction](../../server/src/application/import/mapping.ts), saves it in `bt.imports.extraction` and updates attachment metadata. Ordinary API/SSE responses omit the full extraction.

6. **Server resolves the destination Things.** One candidate is selected automatically. Multiple candidates change the job to `AWAITING_SELECTION` and release the runner. API clients can send `POST /api/imports/{id}:confirm` with candidate IDs and destination Thing IDs (`null` creates a Thing; skipped candidates are omitted). [confirmImport](../../server/src/application/import/commands.ts) allocates targets transactionally, reuses the skeleton for the first new Thing, links the source to each target and requeues the job. Processing resumes using the saved extraction. The current UI displays progress and retry but has no candidate-selection action.

7. **AI maps each candidate — `MAPPING`.** The processor first retains every extracted fact as a custom field, then awaits [OpenAiImports.selectFieldSets](../../server/src/providers/ai/openai-imports.ts) and separate `OpenAiImports.mapFacts` calls:
   - **Choose field sets:** a Responses request asks the model to call `search_field_sets(categoryId, terms)`. When a response contains a `function_call`, `runRegistryConversation()` validates its arguments and invokes the processor's tool callback. The callback runs [registry search](../../server/src/application/registry/search.ts). The adapter adds the result as `function_call_output` and calls Responses again. This loop ends when the model returns schema-valid set IDs.
   - **Fill fields:** the processor expands the selected sets' mandatory dependencies and calls `mapFacts` with the extracted Thing, selected sets and up to 20 facts per awaited request. Each batch starts a fresh conversation with a Thing definition and mapping rules. The prompt selects the Thing's name, category and terms and contains set IDs/names, field IDs/names/descriptions/schemas/sensitivity, and the batch's fact IDs/labels/values/quotes/sensitivity. The model matches selected-set fields first, then searches standalone definitions; uncertain matches stay absent. Its tool loop exposes `search_fields(labels)` and retains outputs, encrypted reasoning and tool results within that batch; calls use `store: false`. The processor rejects mappings for facts outside the batch.
   - **Commit each stage:** the processor validates retrieved IDs, category eligibility, field membership and value types through [applyImportStage](../../server/src/application/import/mapping.ts). It saves selected sets first, then each completed value group, publishing progress after each commit. Source references, sensitive values, unmatched facts and user edits are preserved. All targets finish mapping before discovery starts.

8. **AI researches each Thing — `DISCOVERING`.** [buildResearchContext](../../server/src/application/import/mapping.ts) collects populated fields classified as `instanceSpecific: false` across selected sets, standalone definitions and explicitly classified custom fields. Labels, descriptions, addresses and typed values accompany the context; zero, false and empty strings remain populated. Unclassified fields default to instance-specific. Sensitivity independently controls application masking. Missing eligible fields become enrichment targets; owner-cleared destinations are excluded. Raw uploaded text and other instance-specific values stay outside public-search input. [Category instructions](../../server/src/providers/ai/prompts.ts) define the documents to find, with a fallback for new categories. [OpenAiImports.discover](../../server/src/providers/ai/openai-imports.ts) uses hosted `web_search`, then a tool-free request structures the report against retrieved URLs. The [research workflow](../../server/src/application/import/research.ts) allows two searches within one search-call budget, reserves the second for remaining gaps and considers at most three documents.

9. **AI extracts reference fields; server commits results.** The server downloads cited PDFs through the [PDF provider](../../server/src/providers/web/pdf.ts), preserving its HTTPS, DNS, redirect, size and content checks. The contained `extractDocument` task receives one document, public subject context and up to 20 requested field definitions. It has no search or write tools. It must establish applicability with page/quote evidence, including variant, region and version when relevant, before proposing supported fields. The server validates requested addresses, schema types and evidence bounds. Applicable documents become private attachments; each value batch fills still-empty eligible fields with `DISCOVERY` provenance and attachment/URL/page/quote references under a Thing row lock. Owner edits, clears and removed sets are rechecked at each commit. Progress is published after each document and value batch. Documents are limited to 20 MiB, 100 pages and five field batches each; one retry is allowed for incomplete or invalid extraction output. Unsupported values remain absent.

10. **Server records outcomes and finishes.** Applicable attachments and completed document batches are persisted for retries. Saved bytes and completed batches are reused. Existing cited names, maintenance Events and purchasables retain their persistence and deduplication behavior. `researchOutcomes` reports `FOUND`, `UNAVAILABLE`, `RETRIEVAL_FAILED` or `BUDGET_EXHAUSTED` for resources and missing field addresses. The job becomes `COMPLETE`, or `INCOMPLETE` when retrieval or extraction fails; committed results remain available. Assistant chat retains its explicit maintenance and product research modes.

## Failure and retry

[ImportProcessor](../../server/src/application/import/processor.ts) enforces timeouts and tool budgets. Field-set selection and each fact-mapping batch have separate registry tool-call budgets, controlled by `IMPORT_TOOL_ROUNDS`; the extraction/mapping attempt shares one timeout. An extraction/mapping failure becomes `FAILED` before targets are allocated, or `INCOMPLETE` afterwards; committed results remain available. [ImportProgress.retry](../../src/app/features/things/import-progress.ts) calls `POST /api/imports/{id}:retry`, which requeues eligible jobs. The application uses `ExtractedThing` and `extractedThings`, while persistence and provider wire data retain `candidates`. Public research receives a separate `ResearchContext`. Saved extraction, targets and discovery responses are reused; completed targets are skipped and unfinished mapping is rerun while preserving earlier values and user edits.

SDK transport retries are disabled; document validation retries and persisted application retries have separate bounds. On restart, queued jobs resume; interrupted extraction, mapping or discovery is marked `FAILED` with `interrupted` for explicit retry. `GET /api/imports/{id}` exposes status, candidate summaries while awaiting selection, result IDs, error codes, research outcomes and usage metrics. Usage entries identify the task, model, tokens and request latency; aggregate token counts remain available. See [README configuration and limits](../../README.md#ai-imports).

## Reference extraction model evaluation

`DOCUMENT_EXTRACTION_MODEL` independently selects the contained task's model and defaults to `OPENAI_MODEL`. Model defaults remain unchanged. Text and image inputs and Responses structured outputs are supported by the compared models; [OpenAI file-input guidance](https://developers.openai.com/api/docs/guides/file-inputs) describes PDF text and page-image processing.

Run `node --import tsx --env-file=.env scripts/evaluate-document-extraction.ts` for a **paid** comparison on [labelled synthetic fixtures](../../server/test/fixtures/reference-documents.ts). `--models=model-a,model-b` selects models; `DOCUMENT_EVAL_RATES` supplies USD-per-million input, cached and output rates for additional models. Results, per-task usage, latency and cost including retries are saved in ignored `test-results/document-extraction-evaluation.json`.

The baseline requires all six supported values, correct applicability for all four documents, no incorrect values and verbatim quotes on the labelled pages. It covers a family manual, a typed specification (zero, false, empty text and money), a policy version and an incompatible variant. Two fixtures are PDFs and two are text. Image extraction capability is documented; image quality is unmeasured.

Measured on 4 October 2026, one run per model over the same four documents:

| Model          | Fixtures passed | Supported-field recall | Incorrect values | Citation errors | Total latency | Estimated task cost (USD) |
| -------------- | --------------- | ---------------------- | ---------------- | --------------- | ------------- | ------------------------- |
| `gpt-5.6-sol`  | 4/4             | 100%                   | 0                | 0               | 10.8 s        | $0.022344                 |
| `gpt-5.4-mini` | 3/4             | 33%                    | 0                | 0               | 4.8 s         | $0.003093                 |
| `gpt-4.1-mini` | 4/4             | 100%                   | 0                | 0               | 7.1 s         | $0.001686                 |

`gpt-5.4-mini` rejected the applicable typed specification, omitting four values. `gpt-4.1-mini` was the cheapest passing model in this sample; configure `DOCUMENT_EXTRACTION_MODEL=gpt-4.1-mini` to use it. This baseline measures contained extraction; retrieval success, full-import cost, image quality and broader document coverage remain unmeasured. Defaults require broader evaluation before changing. Costs use the standard rates on the official [Sol](https://developers.openai.com/api/docs/models/gpt-5.6-sol), [5.4 Mini](https://developers.openai.com/api/docs/models/gpt-5.4-mini) and [4.1 Mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini) pages, with input images included in provider token usage. All 12 requests completed without retries.
