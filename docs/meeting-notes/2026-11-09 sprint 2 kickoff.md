Key points and principles:

* Followups from tasks ask user about OUTCOME
* Followups can be structured (suggested outcomes) or a chat
* End result of a followup is new attachment or updated thing field
* Onboarding can create 'skeleton thing' (thing with limited information, no instance identifiers).  Lack of data triggers prompt to user to provide more info.
* Issues are not top level nav \- Issues should be highly promoted while they exist.  Create from Thing view.  Visible on home dashboard.
* Household onboarding can be done without creating collections (they can come later). When we introduce collections, user will choose to add new things to collections explicitly (privacy issue)
